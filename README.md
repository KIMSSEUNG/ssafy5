# 🧠 컨벤션 & 브랜치 전략 가이드

프로젝트에서 효율적인 협업을 위해 Git 사용 시 아래와 같은 규칙을 따릅니다.

---

## 📁 브랜치 전략

기본 브랜치 구조는 Git Flow 전략을 따릅니다:

- `main`: 배포 가능한 최종 안정 버전
- `dev`: 통합 개발 브랜치
- `feature/기능명`: 새로운 기능 개발 시 사용  
  예: `feature/inventory-system`
- `bugfix/버그명`: 버그 수정용 브랜치
- `hotfix/이슈명`: 운영 중 발생한 긴급 수정용

---

## ✏️ 커밋 메시지 컨벤션

커밋 메시지는 다음과 같은 형식으로 작성합니다:

```
[타입]: 간단한 설명 (한글 권장)
```

### 타입 목록
- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `refactor`: 리팩토링 (기능 변경 없음)
- `style`: 포맷팅, 들여쓰기, 세미콜론 등
- `docs`: 문서 추가 또는 수정
- `test`: 테스트 코드 추가/수정
- `chore`: 빌드 설정, 패키지 관리 등
- `merge`: 브랜치 병합

### 예시
```
feat: 플레이어 점프 기능 추가
fix: 애니메이션 전환 오류 수정
refactor: 스폰 시스템 코드 정리
```

협업을 위해 모두가 위 규칙을 준수해주세요! 😄
